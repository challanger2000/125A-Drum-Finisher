# Drum Finisher — DSP research and implementation decisions (2026-10-09)

Status: research / architecture review, **not a sonic release PASS**. Target: `v1.0.0-engineering` (VST3). Do not modify preset/parameter IDs. All suggested ranges are hypotheses until verified by objective, level-matched measurements on independently recorded stereo buses.

4. Zaunschirm, Reiss, Klapuri, *A sub-band approach to musical transient modification*, Computer Music Journal 2012 (publication index): https://c4dm.eecs.qmul.ac.uk/research/publications/ — frequency-dependent transient modification for complex musical material.
5. AudioTK open-source DSP filters (BSD): https://github.com/AudioTK/AudioTK — inspect actual implementation/tests of envelopes, compressor and expander; don't assume API or copy blindly.
6. sevagh, multiband-transient-shaper: https://github.com/sevagh/multiband-transient-shaper — independent differential-envelope implementation; verify license and code before reuse.
7. Chowdhury-DSP, ADAA: https://github.com/jatinchowdhury18/ADAA — nonlinear alias-reduction implementation; compare ADAA and oversampling under controlled IMD/alias benchmarks.
8. DAFx 2024, *Interpolation Filters for Antiderivative Antialiasing*: https://dafx.de/paper-archive/2024/papers/DAFx24_paper_33.pdf — nonlinear broadband aliasing and alternative mitigation. Reference link; this report does not claim detailed verification of PDF equations.
9. *Method for Resonant Frequency Attenuation in Dynamic Audio* (2025): https://www.mdpi.com/2076-3417/15/6/3038 — alternate dynamic-resonance algorithm reference, validate implementation details separately.
10. Grachten, Deruty, Tanguy, *Auto-adaptive Resonance Equalization*, 2018: https://arxiv.org/abs/1807.08636 — detect resonant peaks and attenuate them dynamically.
11. SPL is a commercial method. Existing patent/copyright/license claims must be verified before adopting anyone's code; use generic established concepts or independently implemented mathematics.

## Code-level architectural audit and corrections to evaluate

**PUNCH / TIGHT** — current `src/DrumCore.h` uses fast (2 ms) and slow (55 ms) absolute-amplitude envelopes. PUNCH applies max-channel transient ratio to both channels. TIGHT currently computes `sustain/(attack+0.01)` and 6 dB maximum attenuation. Problem: on normal decays, slow envelope > fast, ratio saturates to 1; this is *not a demonstrated differential-envelope transient-shaper law* and may yield almost time-invariant attenuation during a decay. Increasing the maximum from 3.1 to 6 dB does not correct that topology. **Replace only after side-by-side verification** with level-invariant, fast-vs-slow differential attack/sustain detection (e.g. signed/log envelope difference), shared stereo gain, physically correct coefficient vs sample rate and percussive onset behavior. Preserve dry at zero, avoid abrupt gating. Gate: attack 0–20 ms vs sustain 40–250 ms after onset, both with measured same-gain dry reference; quantify attack retention, tail/attack relative dB, decay time T20 where meaningful, monotonicity 25/50/75/100, tonal effects.

**MASS** — current kick branch is one-pole LP(135 Hz) minus LP(42 Hz) and body branch LP(350 Hz)-LP(110 Hz), parallel with a `tanh` residual at drive 2.5. This is a bounded low-mid coloration, but band-pass cutoff and phase response cannot be inferred as ideal 42–135 or 110–350 Hz brickwall bands. The nonlinear residual is level-dependent and generates harmonics/possible aliasing; no anti-aliasing currently evident in that block. A band boost cannot reliably add true missing kick low-end when input has none. Prefer defining product promise: measured body energy/sustain change, no unwanted DC/sub boom or clipping, controlled harmonics. Do transfer-function sweeps and input-level sweeps, 44.1/48/96/192k, coherent THD/IMD with absolute noise floor and alias rejection compared with 2x/4x reference. Oversampling/ADAA only if audible/quantified aliasing makes it necessary. No arbitrary global MASS coefficient bump. Separate midband masking from kick fundamental rather than a single 'more dB' criterion.

**GLUE** — current detector peak follows 12 ms attack /180 ms release, reference energy `glueRmsEnergy_` tracks **squared peak** (max of L/R) with 350 ms constant; this is not the true two-channel RMS. Relative threshold = 1.35×sqrt(peak-energy moving average); dynamic threshold means compression depends on attack density and can exhibit unusual program dependence. Additional 25/240 ms gain smoothing and 80%-parallel wet attenuation applied by amount. This is a legitimate *creative adaptive compressor* topology, but not a predictable standard feedforward bus compressor. Implement/measure conventional linked stereo energy RMS vs peak detector, defined threshold (possibly relative baseline with calibrated floor), ratio, knee, attack/release and transfer curves; gate: sine level sweeps, repeated isolated kick, sustained drums, gain reduction vs input level and repeat-rate, no pumping, stereo image, CPU. Compare old and standard alternative at matched perceived level before deciding to change existing musical behavior.

**FINISH** — `src/dsp/AdaptiveResonanceSuppressor.cpp` has ten fixed centres 180–6500 Hz, narrow-band detectors, local-neighbour peakiness and up to 24% correlated-band subtraction, transient-onset gate active 18–360 ms. It is **not** a full-band FFT spectral dynamic EQ and can miss off-centre resonances; neighboring band energies also depend strongly on Q, centre spacing and program spectrum. Verify actual notch width and reduction (frequency sweep), resonant snare/tom rings with varying decay, clean cymbal/hi-hat false positives, changing sample rate, onset timing, stereo stability, real latency. Explicitly differentiate resonances that should remain part of a drum tone from unwanted ringing. Freeze detection for musical tones only if demonstrably effective. No 'resonance removal is good' blanket gate.

**Intermodule chain** — PUNCH -> MASS -> TIGHT -> FINISH -> GLUE attenuation -> OUTPUT in actual effective signal flow (FINISH additive delta before final attenuation/output). Ensure true order by inspection, compare factorial tests and combinations. Test full chain on true stereo buses not dual-mono stem duplicates, 0% neutrality, bypass, real-time safety, input/output headroom and offline determinism.

## Evidence/measurement gates and decision process

- Run distinct unit/function tests with explicit signal, expectation and justified tolerance. General CI SUCCESS is only technical regression, not an audio-quality pass.
- Prepare *licensed real stereo drum-bus* tracks from acoustic/live, programmed/metal, electronic/dance; record licensing/provenance. Do not report duplicated mono as evidence of stereo-bus performance.
- Ensure 32/64-bit precision, 44.1/48/96/192k, input gain -18/-12/-6/0/+6 dB where no clip, 25/50/75/100% controls, bypass and automation, module-by-module and combinations, nonfinite and denormals.
- Render matched-output loudness pairs to avoid level bias; also record uncompensated output/headroom. For transients, align events and compare RMS in early/onset/body/tail windows, attack peak, crest factor, low-band spectral energy. For saturation, quantify THD/IMD/alias absolute vs fundamental; for GLUE measure control envelope/gain reduction; FINISH compare resonance decay and nonresonant spectral preservation.
- A listening preference gate is separate from objective DSP correctness and requires genuinely blinded level-matched comparisons by listeners with appropriate playback.
- One coherent change batch, one CI, inspect artifacts, then Windows VST3 full release QA/47 checks at *the same commit*. No early 'final'.
